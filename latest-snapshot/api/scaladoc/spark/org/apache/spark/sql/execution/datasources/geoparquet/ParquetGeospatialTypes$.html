ParquetGeospatialTypes 

object ParquetGeospatialTypes

The GEOMETRY and GEOGRAPHY logical types of the Parquet format, which GeoParquet 2.0 is built on. parquet-java has them since 1.16.0, the version Spark 4.1 ships. Sedona also compiles against the older parquet-java of Spark 3.5 and 4.0, so the types are reached by reflection and supported reflects the library found at run time.

  8.  def crsProperty(crs: Option[JValue]): Option[String]

    The crs property for a CRS as GeoParquet metadata holds it: None for OGC:CRS84, JSON null for an unknown CRS, PROJJSON otherwise.

    The crs property for a CRS as GeoParquet metadata holds it: None for OGC:CRS84, JSON null for an unknown CRS, PROJJSON otherwise. PROJJSON with an identifier becomes authority:code, the form that readers without a PROJJSON parser understand; the GeoParquet metadata of the file keeps the full definition. PROJJSON without one is written inline, and so is PROJJSON whose identifier names a version of its registry: authority:code has no place for the version, and a code can mean another CRS in another version. An authority named srid or projjson stays inline as well, because the Parquet format reads srid:<number> and projjson:<key> as something else.

  9.  def crsToSrid(crs: Option[String], keyValueMetaData: Map[String, String]): Int

    Resolves the crs property of a geospatial logical type to an SRID.

    Resolves the crs property of a geospatial logical type to an SRID. The Parquet format allows inline PROJJSON, authority:code, srid:identifier and projjson:key, where key names a file metadata entry that holds PROJJSON. The key is everything after the colon, so it is looked up as written, white space included.

    returns

    4326 when the property is absent, the EPSG code when the CRS names one, the SRID of Spark's registry of coordinate reference systems when the CRS names another authority the registry knows, and 0 for any other CRS
